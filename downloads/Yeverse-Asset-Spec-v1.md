# Yeverse 通用 3D 藏品资产包规范 · v1

本文件是外部资产制作任务与藏品馆之间的接口协议。制作完成后，用户在手机端选择「添加藏品 → 选择资产包 ZIP」，预览并保存即可。网站无需按商品修改源码。

本规范针对交互展示模型，不要求工程级结构真实性。制作者必须说明哪些是参考图推测、哪些来自真实资料；不要把推测的内部结构描述为厂家确认事实。

## 1. 给另一个 Codex 的任务说明

> 根据我提供的物品参考图，制作符合本规范的 Yeverse v1 资产包。交付一个可以直接导入的 ZIP，根目录只有 manifest.json、model.glb、poster.png。完成轻量的真实三维外形、独立主要零件、中英文说明、组装位置和拆解位移。模型所有材质资源嵌入 GLB，不能依赖外链、运行脚本、专用解码器或网站源码修改。请验证节点对应、拆解与复原、手机性能预算，并说明模型近似之处。可以使用程序建模、已有合法模型或建模工具，具体方式由你决定。

参考图仅用于建模。把三视图或一张拆解图打进 ZIP 不会自动成为三维模型；必须交付真实三角网格。网站负责交互、动画和本地保存，不负责从照片生成模型。

## 2. 容器与版本

文件后缀 `.zip`，使用普通 ZIP（STORE 或 DEFLATE）。根目录严格包含以下三个文件，不要套文件夹，不要加入 README、隐藏文件或脚本：

| 文件 | 内容 | 上限 |
| --- | --- | --- |
| manifest.json | UTF-8 JSON、物品信息与零件定义 | 128 KiB |
| model.glb | glTF 2.0 二进制模型、内嵌几何和 PNG 纹理 | 20 MiB |
| poster.png | 展厅、索引、时间线使用的封面 | 3 MiB、最长边 2048 px |

ZIP 与解压后总量分别不超过 24 MiB。推荐整个包 1–8 MiB。封面建议 1024×1024，完整物体居中，黑灰背景、少文字，不要把 UI 画进封面。

版本字段固定为 `format: "yezi.asset"`、`version: 1`。未来不兼容版本会被拒绝，不会猜测读取。

## 3. Manifest 示例

```json
{
  "format": "yezi.asset",
  "version": 1,
  "assetId": "my-object-001",
  "revision": 1,
  "title": "物品名称",
  "subtitle": "A PERSONAL OBJECT",
  "category": "收藏",
  "model": "model.glb",
  "poster": "poster.png",
  "description": "根据参考图制作的外观与结构示意。",
  "camera": { "direction": [4, 3, 7] },
  "animation": { "durationMs": 1100 },
  "parts": [
    {
      "id": "upper-shell",
      "number": "01",
      "name": "上盖",
      "nameEn": "Upper Shell",
      "description": "保护内部组件的上部外壳。",
      "node": 0,
      "explode": {
        "translation": [0, 0.04, 0],
        "rotation": [0, 0, 0, 1]
      }
    },
    {
      "id": "body",
      "number": "02",
      "name": "主体",
      "nameEn": "Main Body",
      "description": "承托主要部件的主体结构。",
      "node": 1,
      "explode": { "translation": [0, 0, 0] }
    }
  ]
}
```

此例要求 GLB 默认场景顶层节点恰好为 `[0, 1]`。具体生产包应按实际物品定义，不要照搬节点编号。

### 字段规则

| 字段 | 规则 |
| --- | --- |
| assetId | 1–80 位英文字母、数字、点、下划线、短横线；外部资产身份 |
| revision | ≥1 的整数；制作修订号；导入不会覆盖已有藏品，更新请进入该藏品的编辑页更换包 |
| title / subtitle | 名称 1–60 字；副标题最多 100 字 |
| category | 数码、书籍、游戏、礼物、收藏、其他；省略时为收藏 |
| description | 最多 2000 字的资产制作说明；不代替用户自己的故事 |
| camera.direction | 非零三元向量，物品中心指向初始相机的方向；默认 [4,3,7]，距离自动适配 |
| animation.durationMs | 拆解/组装动画时长，400–2000 毫秒；默认 1000 |
| parts | 1–32 个主要零件，建议 4–12 个 |
| parts[].id / number | 稳定英文 ID 与显示编号；各自不可重复 |
| parts[].name / nameEn | 中文名 1–50 字、英文名 1–80 字 |
| parts[].description | 简短说明，最多 800 字 |
| parts[].node | GLB JSON `nodes` 数组的整数索引；按索引绑定，不按名称猜测 |
| explode.translation | 在零件父坐标系内，相对组装位置的 XYZ 位移；每分量 −1000 到 1000，必须有限 |
| explode.rotation | 可省略。单位四元数 [x,y,z,w]；在原始旋转后叠加的局部旋转；不能写欧拉角 |

Manifest 顶层不允许未知字段。字段的机器格式见同套交付中的 `manifest.schema.json`。Schema 检查不能替代 GLB 几何、节点与预算检查。

## 4. 三维模型与零件层级

- 坐标遵从 glTF：右手系、Y 向上，单位为米。按真实比例建模，相机自动适配大小。默认模型视角建议正面朝 +Z。
- 单一场景，默认场景编号为 0；该场景每个顶层节点对应一个主要零件。
- `parts[].node` 集合必须与默认场景顶层 `nodes` 集合完全一致。零件之间不能存在父子关系。
- 每个主要零件内部可以包含多个 mesh 或嵌套子节点，这些网格一起移动、被点选、被特写。
- 不允许闲置节点、共享子节点、循环层级、重复绑定或空零件。
- 模型保存时必须已经处于完整组装状态；不要直接把爆炸图布局当组装位置。
- 顶层零件可使用普通 TRS；推荐烘焙缩放，保持 scale=[1,1,1]。必须为正缩放，不使用镜像/负缩放；matrix 和 TRS 不能同时定义。
- 所有坐标必须有限。顶点每分量绝对值小于 10000；节点变换每分量绝对值小于 1e6。避免零面积、法线错误及交叉面。
- 仅静态三角面（TRIANGLES）。POSITION 使用 FLOAT VEC3，配好 NORMAL；索引使用 unsigned byte/short/int SCALAR。禁止 sparse accessor。
- 仅一个嵌入 BIN buffer。贴图只能是 GLB 内嵌 PNG，每张 ≤2048×2048；无 URI、外部 `.bin`、外部图片或 base64 URI。
- 采用 glTF metallic-roughness PBR 基础材质，唯一允许扩展为 `KHR_materials_unlit`。不使用 Draco、Meshopt、KTX2/Basis、骨骼、morph targets 或预制动画。
- 透明保护罩要控制透明度，避免遮住其他零件。大透明件可能影响射线点选，可使用屏幕编号热点访问内部件。

## 5. 拆解与零件交互

每个零件的目标状态由网站计算：

- 目标位置 = 原始位置 + `explode.translation`。
- 目标旋转 = 原始四元数 × `explode.rotation`；省略时使用单位四元数。
- scale 在拆解中保持不变。

拆解和复原用同一组起终点插值，避免反复操作积累误差。动画采用缓入缓出，遵从系统减少动画偏好。双指缩放和拖动不触发双击。

设计位移时，让结构有合理层次和斜向阅读顺序。上盖、主体、功能组件和底盖分别有空间，避免大量无意义的螺丝占满屏幕。选中零件后网站隐藏其他件、适配相机，显示编号、中英文名与介绍；用户可返回整体或重新组装。

### 推荐验收

1. 完整形态能从正、侧、背面观察，没有纸片式假背面。
2. 拆解后主要零件不互相穿插，四周旋转都成立。
3. 连续拆解与复原至少 5 次不漂移。
4. 每个 mesh 都能归属到一个主要零件；编号热点可作为较小零件的触摸入口。
5. 单个零件特写不会为空、偏离中心或裁切。
6. 360×780 和 390×844 竖屏观察完整与拆解构图，确认编号不会过密。
7. 手机导入、预览、保存、刷新后查看；导出备份再导入，模型仍然可用。

## 6. 手机性能预算

| 项目 | 硬上限 | 建议 |
| --- | --- | --- |
| 顶点总量（按实例累计） | 200,000 | ≤60,000 |
| 三角面（按实例累计） | 120,000 | ≤40,000 |
| 绘制单元/primitive（按实例累计） | 80 | ≤30 |
| 所有节点 | 256 | ≤80 |
| 主要零件 | 32 | 4–12 |
| 纹理 | 8 张 | 1–3 张 |
| 总纹理像素 | 8×1024×1024 | ≤4×1024×1024 |

网站将模型按需加载、限制渲染像素比、暂停不可见和后台渲染，在关闭检视时释放 GPU 资源。此预算不是每款手机流畅的保证，制作者应优先降低绘制单元和纹理内存。

## 7. 导入、保存、更新与备份

- 先校验 ZIP、清单、节点、模型预算、资源引用和引擎可加载性，然后显示预览。无账号、无上传服务器。
- 预览阶段不写入持久化；点击保存后，藏品记录与模型 Blob 在同一个 IndexedDB 事务中提交。失败时保留原数据。
- `assetId` 是制作身份，不是用户藏品 ID。导入相同包可以创建两件藏品；更换已有藏品的模型需在编辑页面完成。
- 模型 Blob 存在独立 assets store，藏品记录仅保存本地资源键和 manifest；不会把临时 blob URL 当永久地址。
- 删除藏品、更换或移除模型时，清理不再被藏品引用的本地模型。普通图片藏品继续使用原流程。
- v4 JSON 完整备份包含藏品、引用模型的 base64 内容、全部已保存的 Galaxy Profile 与有效 Intro 模式；使用明确的 `yeverse.backup` 格式标识和版本号。兼容 v1–v3 及既有无版本旧格式，旧备份不覆盖本地宇宙设置。恢复前校验全部数据与模型，并为模型分配新的本地资源键。
- 导入备份按藏品 UUID 合并，不按名称合并。同 UUID 更新；其他藏品保留。备份文件上限 150 MiB。
- 清除浏览器站点数据会删除本地藏品。定期导出完整备份；浏览器与域名之间不自动同步。

## 8. 示例与交付

- `yeverse-demo-kit.zip`：三层几何模块，直接可导入。
- `yeverse-demo-four-parts.zip`：四层模块，用于确认不同零件数量共用相同引擎。
- `manifest.example.json`：规范实例。
- `manifest.schema.json`：机器可读 JSON Schema。
- `make-asset-examples.py`：无需 Blender 的最小 GLB/ZIP 生成示例，依赖 Python 3 与 Pillow。

示例只用于协议和交互验证，不代表写实建模质量。最终交付时把制作说明放在 ZIP 外部，别把多余文件放入可导入 ZIP。
